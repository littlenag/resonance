## 1. Summary

Resonance is a per-repository system that keeps a **graph database as the source of truth** for a software project: its requirements, design decisions, code units, tests, annotations, and the typed relationships between them. It **projects a standard, fully tool-compatible working tree onto disk**, so build systems, IDEs, git and CI keep working on ordinary files without modification. Agents and developers reach the extra graph information through a **separate API**; the files on disk never show it.

The system's primary purpose is **traceability between intent and implementation**: letting a developer move directly from a requirement to the code that satisfies it and the tests that verify it, and back again, and letting developers annotate and call out code for agents in a structured, durable way. Resonance does not parse source code. Code units are regions of files that people and agents name, and Resonance tracks them through edits by their text. Understanding what the code means stays with agents and language tooling (§2.5).  Of course traceability would not stop at code -- it would continue into the products and artifacts produced by mapping intent all the way through to behavior of the generated solution and back. 

Adoption is **incremental and reversible by design**. A developer first tries Resonance as a purely local overlay that commits nothing (offline mode). A team then shares the graph by committing it next to the code. Developers join one at a time, and each one who opts in makes Resonance their source of truth: first one developer, then a handful of early adopters, then most of the team. Only last, after it has earned trust, is it enforced as the whole team's source of truth. Git stays in use and compatible at every stage. Teammates who have not opted in keep working with plain git, optionally with a quiet helper that lets their agent handle Resonance's bookkeeping (§8.16–§8.21). Onboarding also onboards each developer's agent, which then acts as the first line of enforcement: it runs Resonance's checks so that commits stay consistent with the graph and pull requests merge cleanly (§8.20). The graph store starts as SQLite behind an engine-neutral storage API, so that it can later move to a dedicated graph engine (§8.2.1).
